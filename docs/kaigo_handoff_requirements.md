# 介護施設 申し送りAI — テーマ別要件定義書

## 背景

介護施設の夜勤・日勤交代時、スタッフは口頭または手書きで申し送りを行う。音声メモや走り書きから、申し送り票・経過記録へ転記する時間と漏れが課題になる。

## 課題

- 夜勤終わりに申し送りを書く時間が足りない
- 口語のままでは次の担当者が「何をすべきか」分かりにくい
- バイタル・投薬・家族連絡など、項目の取りこぼしが起きやすい
- デモ商談ではマイク許可・APIキー設定で体験が止まりやすい

## 対象ユーザー

- Primary: 介護施設の管理者・現場リーダー・導入検討者
- Secondary: 夜勤・日勤のケアスタッフ（申し送りを書く／受け取る側）

## 業務シナリオ

1. 夜勤スタッフが利用者の様子を音声メモで残す
2. AI が口語を書き起こし、申し送り票・経過記録のテンプレに整理
3. スタッフが要確認欄を直して提出
4. 日勤スタッフが「要対応」を優先して確認し引き継ぐ

## デモの目的

音声メモ（サンプル音声）から、申し送り票と経過記録のテンプレ下書きが埋まり、人が確認して提出できることを体験してもらう。

## 理想感情

「夜勤終わりにこれなら書ける。次の人も何をすればいいか分かる」

## 書類種

- **申し送り票:** 次シフト向け ToDo・緊急度
- **経過記録:** 対象者・バイタル・水分/食事・特記

## シナリオ（3本）

1. **203 発熱:** 発熱・解熱剤未確認（要対応）。1項目は意図的誤抽出で修正させる
2. **転倒疑い:** 転倒疑い・家族連絡（要対応）
3. **変化なし:** 普通の夜。過検知しないことを見せる

## コンテキスト

- ユニット: 2F さくら
- シフト: 夜勤 22:00–07:00 → 日勤へ
- 対象者: 部屋番号 + フルネーム（例: 203 田中 春子 様）

## Must / Should / Won't

### Must

- サンプル 3 本（API キー不要）で最後まで通る
- 口語の書き起こし表示
- 申し送り票・経過記録の両方をタブで表示
- テンプレ欄が順に埋まる
- 要確認欄のハイライト（色のみ、絵文字なし）
- 1 項目の下書き編集 → 提出
- 提出状態: 下書き → 確認済 → 提出済
- 日勤受信画面（要対応が目立つ一覧）
- Before/After（手書き約 8 分 vs 確認約 45 秒）

### Should

- テキスト貼付入力
- 実マイク（Web Speech API、Chrome 想定）
- マイク失敗時はサンプルへ誘導
- PC 2 ペイン / スマホ縦レイアウト

### Won't（Phase 1）

- `@axeon/ai-demo-core` / Trial 接続
- Whisper 本実装（任意 API は `/api/generate` のみ）
- PDF サーバー生成
- 本物の介護ソフト連携
- ヒヤリハット第 3 書類
- 既存 HTML モックの置き換え

## 画面要件

- ヘッダ: 施設コンテキスト（ユニット・シフト）
- 左: 入力（サンプル / マイク / テキスト）
- 右: 書き起こし + テンプレ下書き（タブ）
- フッター: DEMO / 介護施設向け

## 技術要件

- Next.js App Router（`kaigo_handoff_demo`）
- サンプル経路: クライアント側モック
- Live 経路: Web Speech + テキスト貼付。キーあり時は `/api/generate`（任意）
- 音声ファイル: `public/audio/`（ASCII ファイル名）

## 成功条件

- マイク許可なし・API なしで 3 シナリオすべて提出 → 受信まで通る
- 下書き編集が主役で「AI を信じて終わり」に見えない
- 絵文字 UI なし。文字化け・豆腐が出ない
